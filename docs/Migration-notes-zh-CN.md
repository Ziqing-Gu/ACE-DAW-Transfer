# ACE Studio、Cubase 与 Nuendo 的工程迁移经验

## 工程和轨道存档

独立 CPR 和 NPR 可以同时承载时间线、媒体池和调色板。原生文件还要记录自己的工作目录，轨道和媒体池中的引用必须指向有效对象。Steinberg 轨道存档 XML 适合把选定轨道加入已有工程。目标工程根据自己的色盘解释 XML 中的色号。若选用随 XML 提供的配色底板，其时间线在导入 XML 前为空。

## 剪辑与电平

每个片段分别保存时间线上的可见起点、长度、源偏移、增益和禁用状态。ACE 音频片段的可见起点可由 `pos + clipPos` 得出，单位取决于 `timeUnit`。将拍点和秒换算到同一时间基后再匹配画面。分数采样位置可以标识相邻剪辑的共同边界。轨道推子、片段增益和事件静音是三个不同字段。自动化、调音台总线和设备路由须单独记录支持范围。

## 默认 S 形淡入和淡出

ACE 已确认的默认形状为 `offsetX = 0, offsetY = 0`。设淡化时长为 T，归一化时间为 u = t/T。以下的 g 是线性幅度。

| 形状 | 幅度 g(u) | 四分之一处 | 中点 | 四分之三处 |
| --- | --- | ---: | ---: | ---: |
| 淡入 | 3u² − 2u³ | 0.15625 | 0.5 | 0.84375 |
| 淡出 | 1 − 3u² + 2u³ | 0.84375 | 0.5 | 0.15625 |

Cubase/Nuendo 的原生事件对象分别为 `MFadeIn` 和 `MFadeOut`。在 `MLinearInterpolator` 中记录 1,025 个点，横坐标为 T × 源采样率 × i/1024，纵坐标为 g(i/1024)，i 从 0 到 1024。中点为约 −6.02 dB。这样生成的淡化仍能调整长度与形状。反向识别要比较整条曲线。非默认形状须按实际插值类型处理。选择写入音频时，该侧只应用一次淡化。

## 素材、颜色与第三方插件

- 原始 WAV 和视频可直接引用。原生离线编辑还可能引用时间线上看不到的 Audio 或 Edits 文件。跨系统迁移要重新定位受影响的路径。需要拼接、转码或烘焙时才生成衍生音频。
- ACE 轨道色与标记色分别存储。Steinberg 使用工程色盘和对象色号。未设色、显式设色和继承轨道色具有不同含义。新建原生工程可分配最多 40 个不同色，超过时使用邻近色。点标记在目标宿主中可能继承轨道色。
- VST3 匹配依赖组件 CID、插槽顺序、组件与控制器状态、目标系统扫描结果。旁通、停用和插件内部旁通要分别解释。许可证、外部采样与脉冲响应仍需在目标机器上可用。
- 原生来源工程的路径、指纹和对象映射可支持匹配结构的写回。文件回读能确认事件和状态字段。最终听感还取决于目标宿主中的插件、路由和可用媒体。
